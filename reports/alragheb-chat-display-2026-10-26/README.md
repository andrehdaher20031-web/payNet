# إصلاح عرض تطبيقات الدردشة — 26 أكتوبر 2026

تأكد الفحص من وجود مشكلة فعلية في طريقة تحميل الكتالوج: كان الخادم ينتظر قراءة كل التصنيفات بكامل بياناتها قبل عرض أي منتج. تصنيف ZNET وحده يحتوي 543 منتجًا؛ نجحت قراءته في إحدى المحاولات خلال نحو 15 ثانية، وانتهت محاولات أخرى بخطأ `ALRAGHEB_TIMEOUT`. لذلك يمكن لبطء تصنيف واحد أن يؤدي إلى رسالة خطأ أو تحميل طويل للقسم كله.

الاتصال المباشر بواجهة الراغب نجح بالمفتاح الموجود في إعدادات الخادم المحلي. نجحت قراءة الحساب والقسم الرئيسي، وتطابقت بيانات 716 منتجًا وباقة للدردشات مع القائمة العامة التي تحتوي 907 منتجات. الصورة المرفقة تعرض إعدادات الاتصال، ولا تعرض رسالة خطأ الموقع نفسها؛ أكد المستخدم أن المشكلة رسالة خطأ أو استمرار التحميل.

## ما تغيّر

- تُقرأ بيانات الأسعار مرة واحدة من `/client/api/products`، وتُستخدم قراءة خفيفة للتصنيفات عبر `/client/api/content/:id?base=1` بدل إعادة قراءة الأسعار الكاملة داخل كل تصنيف. دعم الفهرس الخفيف تحقق بطلب فعلي للراغب. يستمر تتبّع التصنيفات المتداخلة، ويُرفض نشر كتالوج ناقص عند عدم تطابق المعرّفات أو التصنيفات بين المصدرين.
- أصبحت مهلة قراءة محتوى التصنيفات 45 ثانية. بقيت مهلة إنشاء الطلب والتحقق المالي 20 ثانية.
- تُحفظ آخر نسخة كاملة في MongoDB لتظل متاحة بعد إعادة تشغيل الخادم. ترتبط النسخة ببصمة حساب المزوّد، ولا تخزّن المفتاح نفسه. البيانات التي مضى على تحديثها أكثر من ساعة لا تُستخدم كنسخة صالحة للعرض الاحتياطي.
- يُعرض الكتالوج المحفوظ فورًا أثناء تحديثه في الخلفية، مع بيان واضح لحالة التحديث. لا يحل تحديث جزئي محل النسخة الكاملة السابقة.
- تأكيد الشراء يستمر في انتظار الكتالوج المحدّث والتحقق المباشر من المنتج؛ النسخة القديمة لا تتجاوز فحص السعر أو الصلاحيات.
- تُحدّث الواجهة العرض بعد اكتمال التحديث في الخلفية، ولا تبدأ دورة تحميل طويلة أخرى تلقائيًا بعد انتهاء مهلة المزوّد أو المتصفح.
- يبدأ تجهيز الكتالوج بعد تشغيل الخادم دون تأخير الاستماع للطلبات.

| بناء الواجهة للإنتاج | ناجح؛ تحذيرات lint سابقة خارج ملفات الإصلاح |
| مطابقة الكتالوج المباشر | 716 سعرًا وقاعدة كمية متطابقة؛ 5 تصنيفات فرعية |
| متصفح الكمبيوتر والهاتف | 8 سيناريوهات ناجحة |
| جلب الكتالوج الأول في اختبار المتصفح | 20.815 ثانية؛ يعتمد على استجابة المزوّد |
| ظهور العرض المحفوظ أثناء تحديث معلّق | 852 ملّي ثانية، شاملة تحميل الصفحة في الاختبار |

شمل اختبار المتصفح العرض والتصنيفات، الصفحة الثانية من ZNET، البحث وتفاصيل المنتج، عرض الهاتف دون تجاوز أفقي، كتالوج الإدارة، عرض البيانات أثناء تحديث معلّق، استمرار العرض عند تعطل المزوّد، ورسالة خطأ دون إعادة محاولة تلقائية طويلة عند عدم وجود نسخة محفوظة.

استُخدم كتالوج الراغب الحقيقي مع مستخدم وسجل طلبات وهميين في اختبار المتصفح. لم يتصل الاختبار بقاعدة بيانات التطبيق، ولم يُنفّذ أي طلب شراء. اختبارات المعاملات والتخزين الدائم استخدمت قواعد MongoDB معزولة. هذه النتائج لا تعني نشر التعديل أو نجاح عملية شراء مالية على الموقع المنشور.

## تطبيق الإصلاح على الموقع

الإصلاح منفّذ في الملفات المحلية. إعدادات الواجهة الحالية تشير إلى `https://paynet-1.onrender.com`؛ تعديل الملفات المحلية وحده لا يغيّر نسخة Render. يلزم نشر تعديلات الخادم والواجهة، مع وجود `ALRAGHEB_API_TOKEN` في إعدادات الخادم المنشور وتمكين الكتالوج، ثم إعادة تحميل الصفحة. لا يوضع مفتاح الراغب داخل إعدادات الواجهة.

لإعادة التحقق محليًا:

```powershell
npm run test:alragheb
npm run verify:alragheb:live
npm run verify:alragheb:display
```

الأمر الأخير يتوقع نسخة مبنية من الواجهة في `C:\andreh\payNet-frontend-main\build`، ويقرأ كتالوج الراغب دون تنفيذ شراء. يمكن تحديد مشروع واجهة مختلف عبر `PAYNET_FRONTEND_DIR`.

مرجع الاتصال العام: [توثيق API الرسمي للراغب](https://api.alragheb-store.com/api-docs).
